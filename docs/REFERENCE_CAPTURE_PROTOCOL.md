# Reference Capture Protocol

21st.dev and MotionSites are browser reference resources, not installed skills. Use them to raise component, layout, and motion quality before implementation, then translate the idea into the niche and repo constraints.

## When Required

Capture references before implementation when a task needs:

- A new premium mini-site concept.
- A new section architecture or major component pattern.
- A signature motion or interaction moment.
- A component copied or adapted from an external source.
- Evidence that the result is not a same-template reskin.

## Required Reference Record

Every captured reference must include:

- **URL**: Exact page or component URL.
- **Screenshot/proof path**: Local screenshot or browser proof artifact from the current research pass.
- **Component/pattern name**: Clear name such as hero reveal, split booking CTA, kinetic gallery, archive rail, or intake flow.
- **License/usage note**: Whether copying is allowed, unknown, or requires manual rewrite only.
- **Dependency impact**: New dependency required, existing dependency sufficient, or dependency-free adaptation.
- **Borrowed idea**: What is being borrowed: layout, motion timing, interaction behavior, component structure, typography rhythm, CTA pattern, or asset treatment.
- **Niche translation**: What must change so the reference belongs to the target business and audience.
- **Why adapt instead of handbuild**: Why this reference prevents weak approximations or raises quality.

## Component Copy Policy

Copying or closely adapting component code is allowed only when all of these are true:

- The license permits the intended use, or the implementation is rewritten from observation rather than copied.
- The component is scoped to the task and does not become a generic component dump.
- Dependencies are already present or explicitly approved.
- The pattern is translated to the niche, brand, copy, assets, and conversion path.
- Mobile and desktop QA prove it works in the actual page.
- The final result feels designed, not pasted.

Reject component copying when it creates style mismatch, dependency bloat, weak semantics, unlicensed reuse, inaccessible interaction, or a layout that ignores the target niche.

## Browser Capture Workflow

1. Open the reference with the Browser plugin.
2. Capture a screenshot or focused proof artifact.
3. Record the reference fields above in the task plan or PR report.
4. Decide whether to copy, adapt, or only use as inspiration.
5. After implementation, verify the adapted result with the QA playbook.

Do not use 21st.dev or MotionSites as a substitute for taste judgment. They provide raw reference material; the builder must still make a specific design decision.
