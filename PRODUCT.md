# Product Context

## What This Repo Is

This repo is a repeatable premium mini-site generation workflow. It combines a Vite/React demo site, documented QA gates, council review, asset strategy, prompt discipline, and real Codex design resources so future tasks can produce better client-acquisition mini-sites with less drift.

The current demo site is Obsidian Ink Studio, a luxury tattoo concierge in Pune. It is a working reference surface, not the final product by itself.

## Business Goal

The goal is to help Amitabh create sellable, client-ready mini-sites that can win real clients and make real money. The repo should not become an endless polish loop around one demo. Each serious branch should improve the repeatable workflow, the proof standard, or the quality of a specific client-facing output.

Likely buyer categories include small businesses, creators, local premium services, niche client offers, and people who need high-quality one-page client-acquisition sites. These are examples, not a fixed market list.

## Output Quality

Sellable mini-sites should feel image-led, motion-aware, conversion-clear, mobile-safe, premium, and non-generic. Quality is judged in the rendered page, not in the prompt or explanation.

A strong output should:
- Start from a niche-specific concept and audience.
- Use section architecture that fits the offer.
- Make the CTA obvious and reachable.
- Use assets that carry the service promise.
- Include motion or interaction only when it improves story, feedback, or memorability.
- Prove desktop and mobile behavior separately.
- Avoid same-template reskins.

## Reel-Level Target

"Reel-level" is a target benchmark, not a claim that the current repo already reaches it.

Operationally, reel-level work should show:
- Strong first-screen impact.
- A niche-specific concept, not a skin over the previous demo.
- Reference-backed visual and motion choices.
- At least one memorable interaction or motion moment.
- A strong CTA path.
- No same-template reskin.
- Current browser and QA proof.

Use `docs/CAPABILITY_TEST_GATES.md` as the gate for any task claiming premium, client-ready, motion-aware, or reel-level output.

## First Capability Test

The first serious reel-level capability test must prove that the workflow can create a new or substantially differentiated premium mini-site direction using the installed skills, browser references, asset strategy, motion judgment, and QA gates correctly.

It must prove more than "the build passes." It should demonstrate:
- Concept-first planning.
- Reference capture before implementation.
- Skill usage proof that names real installed skills or plugin resources.
- Asset richness that is not generic or label-led.
- A memorable but purposeful interaction.
- Conversion clarity.
- Mobile proof at 390px and 412px.
- No same-template reskin.
